# 09. ver5 — JSON 실행 기록 뷰어

[README](../README.md) · [V4 파일 형식](08-ver4-file-io.md) · [검증 결과](04-testing.md)

## 목표

V4는 결과를 JSON으로 저장했지만 실행 구간을 콘솔 텍스트로만 확인했습니다.
V5는 그 JSON을 브라우저에서 읽어 시간 축과 현재 상태를 함께 보여줍니다.
C 스케줄러는 그대로 두고 `viewer/`에 의존성 없는 HTML·CSS·JavaScript를 추가했습니다.

| 기능 | 동작 |
| --- | --- |
| 기본 예제 | V5에서 생성한 `ver5-sample/results.json`을 첫 화면에 표시 |
| JSON 열기 | 파일 선택 후 브라우저 메모리에서 검증·표시 |
| 알고리즘 탭 | FCFS, SJF, RR 중 상태 확인 대상 선택 |
| 시간 이동 | 슬라이더, 처음, 이전 구간, 다음 구간 |
| 재생 | 0.5×~4× 속도, 일시정지, 완료 시 정지 |
| 현재 상태 | CPU, 대기·완료·미도착 개수, 작업별 실행·남은 시간 |
| 비교표 | 평균 대기·반환·응답, 전체 완료 시각 |

계산 엔진의 출력이 바뀌지 않도록 뷰어는 작업을 다시 스케줄링하지 않습니다.
파일의 스키마·통계·타임라인을 검증하고 화면 상태만 계산합니다.

## 로컬 실행

Node.js 18 이상에서 프로젝트 루트 기준으로 실행합니다.

```powershell
node scripts/serve-viewer.js 8787
```

서버는 `127.0.0.1`에서 `viewer/`의 고정된 여섯 파일만 제공합니다.
허용 목록에 없는 경로와 GET·HEAD가 아닌 요청은 404입니다.
포트를 `0`으로 지정하면 운영체제가 임시 포트를 선택합니다.

브라우저에서 `http://127.0.0.1:8787/`을 열면 V5 기본 예제가 표시됩니다.
`JSON 파일 열기`로 V4/V5 `results.json`을 선택하거나 기본 예제를 다시 불러올 수 있습니다.
서버는 파일을 업로드하거나 결과를 저장하지 않습니다.

## JSON 검증

[`viewer/model.js`](../viewer/model.js)의 `prepare`는 표시 전에 다음을 확인합니다.

1. schema 버전, semantic 프로그램 버전, ticks 단위와 단일 CPU 가정.
2. 입력 ID·도착·실행 범위와 중복.
3. 알고리즘의 policy와 RR 시간 할당량.
4. 작업별 시간 계산과 평균 요약.
5. 타임라인의 연속성, IDLE 조건, 도착 전 실행, RR 구간 상한.
6. 작업별 실행량, 최초 시작, 최종 종료, 전체 완료 시각.

파일은 16MB까지만 읽습니다. 실패하면 기존 화면을 바꾸지 않고 오류 메시지를 표시합니다.
타임라인을 따라 상태는 다음 규칙으로 계산합니다.

```text
time < arrival       → pending (미도착)
time >= completion   → complete (완료)
현재 구간의 작업    → running (실행 중)
그 외 도착한 작업   → waiting (대기)
```

RR의 여러 구간은 각 구간 이전의 누적 실행량을 합산합니다.
이전·다음 버튼은 타임라인의 구간 끝 시각 배열을 사용합니다.

## 화면 구조

왼쪽에는 파일 선택, 현재 CPU와 작업 수 요약을 두고, 본문에는 타임라인·재생 조작·작업 상태·전체 비교표를 배치했습니다.
각 알고리즘 타임라인은 Canvas에 그리며 실행 작업은 입력 ID 순서의 색, IDLE은 회색으로 표시합니다.
좁은 막대에는 ID를 생략하고 아래 표에서 같은 정보를 제공합니다.

740px 이하에서는 사이드바가 위로 이동하고, 420px 이하에서는 보조 CPU 패널을 숨겨 타임라인과 조작 공간을 우선합니다.
버튼·파일 선택·슬라이더에는 키보드 포커스 표시와 레이블을 제공합니다.
Canvas에는 `role=img`와 `aria-label`을 두고, 상태 표에 동일한 작업 상태를 텍스트로 표시합니다.
탭이 숨겨지면 재생을 멈춰 백그라운드에서 시간이 계속 흐르지 않게 합니다.

## V4 JSON과 샘플

`examples/ver5-sample/results.json`은 C V5 실행 파일로 생성한 대표 입력입니다.
`scripts/sync-viewer-sample.js`는 이 JSON을 검증한 뒤 `viewer/sample-data.js`로 복사합니다.
샘플과 모델이 달라지면 동기화 단계가 실패합니다.

V5는 V4 JSON schema 1을 그대로 읽습니다. 따라서 V4에서 생성한 JSON도
조건과 통계 필드가 올바르면 열 수 있습니다. 화면에는 원본 엔진 버전이 표시됩니다.

## 코드 책임과 경로 안전

| 파일 | 책임 |
| --- | --- |
| `viewer/model.js` | JSON 검증, 구간 조회, 작업 상태와 이동 시각 계산 |
| `viewer/app.js` | 파일 선택, Canvas, 재생, 표와 오류 화면 갱신 |
| `viewer/style.css` | 색·간격·반응형 화면·포커스 스타일 |
| `viewer/index.html` | 접근 가능한 화면 구조와 로컬 파일 입력 |
| `scripts/serve-viewer.js` | 루프백 고정 정적 미리보기 서버 |

Node 서버는 요청 경로를 파일 경로로 조합하지 않고 고정된 허용 목록에서만 선택합니다.
따라서 C 소스, 빌드 산출물, reports, 임의의 상위 경로를 서버가 반환하지 않습니다.
호스트가 `127.0.0.1`로 고정되어 외부 공개 서버로 동작하지 않습니다.

## 제한과 다음 단계

뷰어는 JSON/CSV를 수정하거나 C 엔진을 실행하지 않습니다. 브라우저별 Canvas 픽셀 일치,
모바일 보조 기술 조합, 실제 인터넷 호스팅은 검증 범위가 아닙니다.
긴 RR 기록은 JSON을 모두 검증하지만 화면에 모든 ID를 그리지는 않습니다.
현재 모델에는 I/O, 문맥 교환 비용, 다중 CPU가 없습니다.

V6에서는 현재 알고리즘·파일·뷰어 검증을 유지하면서 대규모 입력 성능과 결과 파일 필터를 실험할 예정입니다.
