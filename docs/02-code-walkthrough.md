# 02. 함수별 코드 분석

[README](../README.md) · [이전: 설계](01-design.md) · [다음: 실험](03-experiments.md)

이 문서는 V1 학습 기록입니다. 분석 대상은
[v1.0.0의 src/main.c](https://github.com/jdonghyeon462-cloud/cpu-scheduling-simulator-ver1/blob/v1.0.0/src/main.c)입니다.
현재 V2에서는 계산 함수를 `scheduler.c`로 분리했습니다.
변경된 함수 구성은 [V2 상세 분석](06-ver2-sjf.md)에서 설명합니다.
먼저 `main`으로 전체 흐름을 읽고 아래 함수들을 순서대로 확인하면 됩니다.

## 1. main: 입력 → 계산 → 출력

```c
Process processes[MAX_PROCESSES] = {0};
```

최대 100개의 구조체를 만들고 모든 필드를 0으로 초기화합니다.
입력 개수는 먼저 `long long`으로 읽고 1~100 범위를 확인한 뒤 `int`로 변환합니다.
따라서 큰 입력이 변환 과정에서 잘려 배열 범위 검사를 우회하지 않습니다.

입력 반복문은 `i < count`까지 실행하며 ID는 `i + 1`로 부여합니다.
두 시간 입력 중 하나라도 실패하면 `EXIT_FAILURE`로 종료합니다.
입력이 끝나면 `simulate_fcfs`와 `print_results`를 호출합니다.

## 2. read_integer: 정수 입력과 재입력

입력은 `fgets`로 한 줄을 읽고 `strtoll`로 10진 정수로 변환합니다.
단순히 숫자 앞부분만 읽고 성공 처리하지 않도록 변환이 끝난 위치도 검사합니다.

| 입력 | 처리 | 이유 |
| --- | --- | --- |
| `12` | 허용 범위 안이면 성공 | 정상 정수 |
| ` 12 ` | 허용 범위 안이면 성공 | 앞뒤 공백 허용 |
| `12abc` | 재입력 | 숫자 뒤에 다른 문자 존재 |
| `1.5` | 재입력 | 정수만 허용 |
| 빈 줄 | 재입력 | 변환할 숫자가 없음 |
| 매우 큰 정수 | 재입력 | `strtoll` 범위 초과 |
| 도착 `-1` / 실행 `0` | 재입력 | 필드의 허용 범위 위반 |

`errno = 0`으로 초기화한 뒤 `ERANGE`를 확인해 정수 변환 오버플로를 감지합니다.
`end == line`은 숫자가 하나도 변환되지 않았다는 뜻입니다.
변환 후 남은 공백을 건너뛰고 문자열 끝인지 검사합니다.

`isspace((unsigned char)*end)`의 형 변환은 음수인 `char` 값이
문자 분류 함수에 직접 전달되지 않도록 합니다.

128바이트 버퍼를 가득 채웠는데 줄바꿈이 없으면 나머지 줄을 비웁니다.
그렇지 않으면 긴 입력의 뒷부분이 다음 질문의 답으로 잘못 사용될 수 있습니다.
이 함수는 사람이 입력하는 텍스트 줄을 위한 것이며 임의의 바이너리 파일 파서는 아닙니다.

출력 매개변수인 `long long *result`에는 모든 검사가 성공한 뒤에만 값을 씁니다.
`fflush(stdout)`은 입력 대기 전에 프롬프트가 화면에 보이도록 합니다.

## 3. sort_by_arrival: 동시 도착 순서 보존

```c
while (j >= 0 && processes[j].arrival_time > current.arrival_time) {
    processes[j + 1] = processes[j];
    --j;
}
```

현재 원소보다 늦게 도착한 원소를 오른쪽으로 옮겨 삽입 위치를 만듭니다.
`>`를 `>=`로 바꾸면 같은 시각의 기존 원소까지 밀어내므로 입력 순서가 바뀝니다.

`j >= 0`을 먼저 검사하는 것도 중요합니다.
C의 `&&`는 왼쪽이 거짓이면 오른쪽을 평가하지 않으므로 `processes[-1]`에 접근하지 않습니다.
구조체 대입은 ID와 모든 시간 필드를 함께 복사합니다.

## 4. simulate_fcfs: 가상 시계 이동

```c
if (current_time < process->arrival_time) {
    current_time = process->arrival_time;
}
```

시각 5에 CPU가 비었는데 다음 작업이 8에 도착한다면 바로 8로 이동합니다.
유휴 구간의 모든 tick을 반복하지 않으므로 입력 시간의 크기만큼 반복문이 늘어나지 않습니다.

`Process *process = &processes[i]`는 배열 원소의 주소를 저장합니다.
따라서 `process->start_time` 등에 대입하면 원본 배열의 값이 바뀝니다.
각 작업을 끝까지 실행한 뒤 현재 시각을 그 종료 시각으로 갱신합니다.

## 5. print_results: 계산과 표시 분리

인자는 `const Process processes[]`입니다.
출력 함수가 전달받은 프로세스 정보를 수정하지 않는다는 의도를 표현합니다.

첫 반복문은 실행 구간과 `IDLE`을 출력하고,
두 번째 반복문은 표를 출력하면서 대기·반환 시간 합계를 계산합니다.
`snprintf`는 ID를 고정 크기 문자 버퍼에 길이를 제한해 작성합니다.

```c
(double)total_waiting / count
```

합계를 먼저 실수로 변환하므로 정수 나눗셈으로 소수부가 사라지지 않습니다.
`%.2f`는 출력할 때 소수 둘째 자리까지 반올림합니다.

## 6. 왜 시간에 long long을 사용하는가?

시간 입력 하나는 1,000,000 이하이지만 누적값은 훨씬 커질 수 있습니다.
100개가 동시에 도착하고 각각 1,000,000 tick을 실행하면 대기 시간 합은 다음과 같습니다.

```text
(0 + 1 + ... + 99) × 1,000,000 = 4,950,000,000
```

이는 일반적인 32비트 signed int의 최댓값 2,147,483,647을 넘습니다.
시간 필드와 합계에 `long long`을 사용하고 출력에도 `%lld`를 맞췄습니다.

## 7. 직접 바꿔보며 이해하기

1. `basic.txt`에서 P2 도착 시간을 1에서 6으로 바꾸고 IDLE이 생기는지 예측합니다.
2. 동시 도착의 입력 순서를 바꾸고 ID와 실행 순서를 함께 확인합니다.
3. 평균 계산의 `(double)`을 제거했을 때 출력이 어떻게 달라지는지 생각해 봅니다.
4. 변경 후 [자동 테스트](04-testing.md)를 실행해 기존 조건이 유지되는지 확인합니다.

알고리즘 구현을 나누면 변경 이유가 분명해집니다.
