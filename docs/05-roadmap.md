# 05. 버전별 개발 계획

[README](../README.md) · [이전: 테스트](04-testing.md)

현재 구현은 ver5의 세 알고리즘·비교·파일 입출력·JSON 실행 기록 뷰어까지입니다. ver6 이후는 계획입니다.

## ver1: C 기반 FCFS 완성본

- 입력, 안정 정렬, 실행 및 유휴 구간 표시.
- 대기·반환 시간 계산, 입력 검증.
- 소스, 문서, 예제, 테스트, 빌드 스크립트 정리.
- 완성본을 `v1.0.0` 태그로 기록.

완료 기준은 예제의 손계산과 자동 검증이 일치하고, README만 보고 빌드할 수 있는 것입니다.

## ver2: 비선점 SJF와 비교 — 완료

현재 준비된 작업 중 실행 시간이 가장 짧은 작업을 선택합니다.
**전체 작업을 실행 시간으로 한 번 정렬하는 것만으로는 충분하지 않습니다.**
아직 도착하지 않은 작업은 현재 선택 후보에서 제외해야 합니다.

- FCFS/SJF 선택 메뉴 추가.
- 동률 규칙을 실행 시간 → 도착 시간 → 입력 순서로 문서화.
- 동일한 원본 입력을 복사해 각 알고리즘 실행.
- 알고리즘이 바꾼 배열이 다른 알고리즘의 입력 순서를 오염시키지 않도록 분리.
- 공통 `Process` 정의와 계산 함수를 필요에 따라 헤더·소스 파일로 분리.

`src/scheduler.h`, `src/scheduler.c`로 분리했고, 기존 입력을 유지하는 CLI와 선택 메뉴를 구현했습니다.
[상세 구현과 실험](06-ver2-sjf.md), [검증 결과](04-testing.md)에 완료 내용을 기록했습니다.

검증 예제: P1=(0, 5), P2=(1, 4), P3=(2, 1).
FCFS는 P1 → P2 → P3, 비선점 SJF는 P1 → P3 → P2입니다.
이 경우 평균 대기는 FCFS 11/3, SJF 8/3입니다.

## ver3: Round Robin — 완료

- 원형 큐로 준비 큐 구현.
- 시간 할당량과 남은 실행 시간 저장.
- 하나의 프로세스가 여러 구간에 나타날 수 있는 실행 기록 배열 추가.
- 실행 중 도착한 작업을 준비 큐에 반영.
- 시간 할당량이 끝나는 시각의 새 도착과 재삽입 순서를 명시.

현재 `시작 - 도착`은 최초 응답 시간에 해당합니다.
V3에서 총 대기는 문맥 교환 비용 0, I/O 없음이라는 가정하에
`종료 - 도착 - 총 실행 시간`으로 계산해야 합니다.
완료 기준은 큐가 가득 찼을 때의 처리, 경계 시각 도착, 큰 시간 할당량을 포함한 검증입니다.

V3에서는 원형 큐, 동적 실행 기록 배열, RR·비교 모드의 시간 할당량 입력,
평균 응답 시간을 구현했습니다. 실행 구간 끝 시각까지 도착한 작업을 먼저 넣고 현재 작업을 재삽입합니다.
구체적인 구현과 검증 결과는 [V3 분석](07-ver3-round-robin.md)과 [테스트 문서](04-testing.md)에 있습니다.

## ver4: 결과 저장과 비교 실험 — 완료

- 입력 데이터의 저장·불러오기 기능.
- CSV/JSON 결과 내보내기.
- 동일 입력에 대한 알고리즘별 평균 대기·반환·응답 시간 비교.
- 실험 조건과 동률 규칙을 결과에 함께 기록.

실행 파일과 재생성 가능한 결과는 `build/` 등에 보관하고,
대표 입력·기대 결과만 `examples/`나 `tests/`에서 관리합니다.

기존 텍스트 입력 형식을 직접 읽고 다시 저장하는 로더를 구현했습니다.
CSV는 작업별 결과·평균·실험 조건을 담고, JSON은 원본 입력과 전체 실행 구간도 포함합니다.
개인 실험 결과는 Git에서 제외한 `reports/` 아래에 저장할 수 있습니다.
[V4 분석](08-ver4-file-io.md)과 [검증 기록](04-testing.md)에 상세 내용을 정리했습니다.

## ver5: 실행 과정 시각화 — 완료

C 엔진이 생성한 실행 기록을 바탕으로 시간 축, 단계 실행, 일시정지를 제공합니다.
JavaScript를 배우면 웹 화면에서 JSON 기록을 읽는 방식으로 확장할 수 있습니다.
계산 함수가 화면 코드에 의존하지 않도록 유지하는 것이 준비 단계입니다.

V5에서는 `viewer/`에 의존성 없는 HTML·CSS·JavaScript 뷰어를 추가했습니다.
V4 JSON의 스키마·통계·타임라인을 검증한 후 알고리즘 탭, 시간 슬라이더, 재생·일시정지,
구간 단위 이동, 작업 상태 표와 비교표를 표시합니다.
Node.js 기본 HTTP 서버는 루프백에서 뷰어 파일만 제공하며 JSON은 브라우저에서 직접 선택합니다.
[V5 분석](09-ver5-viewer.md)과 [검증 기록](04-testing.md)에 상세 내용을 정리했습니다.

## 저장소와 버전의 관리 규칙

현재 프로젝트 폴더와 저장소 이름은 `cpu-scheduling-simulator-ver1`입니다.
V1 안에 다시 `ver1/ver1` 같은 중첩 폴더를 만들지 않습니다.

후속 버전을 별도 저장소로 만들 경우에도 `src/`, `docs/`, `examples/`, `tests/`, `scripts/` 구조를 유지합니다.
현재 V5도 같은 저장소에서 이어가며 주소를 보존했습니다.
V1부터 V5까지 `v1.0.0`·`v2.0.0`·`v3.0.0`·`v4.0.0`·`v5.0.0` 태그로 완성본을 구분합니다.
어떤 방식을 택하든 기존 `v1.0.0` 태그를 다른 커밋으로 이동하지 않아야 V1을 다시 확인할 수 있습니다.

학습 기록은 실제로 바꾼 이유와 확인 결과를 작성합니다.
아직 구현하지 않은 기능을 README의 완료 기능으로 표시하지 않습니다.
